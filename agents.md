# Storybook Development Policy

To maintain a clean and maintainable codebase, all Storybook development must adhere to the following principles:

- **Lean Environment**: Storybook must remain lean. No boilerplate, default examples, or unnecessary assets/files.
- **Strictly Functional**: Only add stories that document actual components or application views.
- **To the Point**: Keep stories minimal and focused on essential usage scenarios. Avoid "flab."
- **Component Focused**: Storybook is to be used solely for component isolation and testing.

# Git Commit Policy

- **Manual Commit Only**: Git commits must only be performed when explicitly requested by the human user after they have reviewed the code. Automated commits are prohibited.
